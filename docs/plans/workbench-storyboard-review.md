# 工作台一致性与单镜审图

目标：沿用现有 CLI 出片；补齐本地 key 保存、单镜画图提示词编辑与局部重出、成熟播放器。

## 执行步骤

1. 核对 CLI / SKILL / prompts 与 UI：真实调用已一致；修复 one 默认时长、seed/check、视觉 key 过度预检，复用 film.load 时间处理，显式提供 JSON 所在目录。验证：同一输入得到同一规范化结果和命令参数。
2. 配置保存：沿用 .env，页面可保存到本机 .env 或只用当前服务；保存不回显 key、权限 0600、原子替换、保留其它配置。验证：重启加载、key 不出现在 API 响应或任务记录。
3. 分镜审图：新增只画分镜阶段，直接调用 film.stage_frames；卡片显示原 frames.prompt / 实际状态 prompt；单图通过 frames.draw，独立记录新任务号、临时图片成功后替换，失败保留原图并续查新任务。验证：只调用目标图片、保留其他图片、失败续跑不重复提交。
4. 更新视频：重出分镜仅标记片段待更新，不自动调用视频 API。用户继续时复用原 film.run 与从 --redo 提取的共享失效函数，失效只应用一次以保证恢复不会重复清空新 task；shot 更新所属段，first 沿用 CLI 下游失效规则，none 不提供审图操作。验证：更新前旧视频显示待更新，成功后恢复。
5. Plyr：固定版本 JS/CSS/SVG/许可本地分发；控件文字来自中英 JSON。验证：浏览器播放、进度拖动、全屏/音量及单镜编辑完整路径。
6. 写简短对照与使用说明，运行离线/模拟 API 验证，不用真 key、不产生费用。

## 关键边界

- 画图提示词与视频六段式提示词严格区分。前者直接用于 frames.draw，后者继续使用官方指南、RULES 与 prompts/h3_examples.md。
- 修改首张锚图不擅自重画所有分镜；后续重画才使用新锚图。
- 先只画分镜只需要 APIMart，不应要求 RunningHub 或 LLM key。
- 生成过程互斥；新 prompt 不复用旧 task；失败续跑复用 pending task。
- Claude 按既有用户约束保持禁用，工作台明确使用 llm；这是配置选择，不另写改写逻辑。
- 临时验证脚本清理；修复已存在偏差的回归测试保留（遵循用户规则 15，优先于临时测试清理规则）。
