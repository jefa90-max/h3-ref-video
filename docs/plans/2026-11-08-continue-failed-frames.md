# 单张分镜失败后继续批次

## 行为

分镜图单项生成失败后保存提示词、任务号和失败原因，继续处理所有后续分镜；正常续跑跳过已保存的失败项，不重新付费生成。用户从卡片手动处理失败项。审核拒绝仍要求先手工改词。

首张分镜失败时，后续分镜继续使用原角色图和场景总表，不附加不存在的首镜锚图。记录实际使用的锚图，保证卡片的参考图编号与提交提示词一致。

批次完成后显示失败项待处理。保留已有成功图片，单张手动重生成成功后清除该项失败标记。缺图或仍有失败项时不进入视频提交；CLI 完成其余分镜后返回任务目录，工作台留在分镜审阅阶段。

## 验证

1. 首张审核拒绝：后续图均实际尝试生成，无缺失锚图，失败项仅一次提交。
2. 中间普通失败、全部失败：批次不提前抛错，保存逐项失败，正常续跑不重复提交。
3. 成功项文件保持；失败卡片可编辑，首图修复后其它卡片仍反映原生成时的参考图。
4. 全量离线测试、编译与 JS 语法检查；重打 Windows 包并核对文件清单与摘要。不启动服务、不调用真实生成或 Claude。

## 验证结果

已实现逐项失败后继续、缺失首镜锚图降级、实际参考图持久化、失败卡片手动恢复和部分批次状态。缺图不进入视频生成，也不记录虚假的成功拼接。普通续跑不重复提交失败项，包含消息为空的超时异常。

Python 全量 111 项（107 通过、4 Windows 跳过），JavaScript 16 项通过；编译、语法、语言键与 diff 检查通过。Windows 更新包 continue-after-failure.zip 已生成并校验 65 个源文件、摘要及干净解压运行边界。未启动服务或付费生成，Windows 真机和界面体验交付用户验收。
