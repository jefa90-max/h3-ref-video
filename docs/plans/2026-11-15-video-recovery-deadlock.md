# 部分视频失败后的恢复死锁修复

用户已确认修复。仅修复恢复流程，不调用真实生成、不修改已有任务、不启停服务。

## 成功标准

- 已审核、已执行重生成失效处理的旧任务，刷新后允许手动重试明确失败的片段。
- 每个失败片段由用户明确点击才创建新的付费尝试；未知提交和已接单任务仍保持保护。
- 修复多个失败片段后，可以继续原批次；已有成功片段原样保留，已接单片段只续查，未提交片段正常开始。
- 新修改或尚未应用的分镜更新仍必须确认，不能被旧 `reset_applied` 标记吞掉。

## 根因与最小方案

`dirty_segments` 保留到整片成功，但 `request.reset_applied=true` 已证明 `request.redo` 指定片段的旧视频失效处理完成。原恢复界面忽略这个区别，误将清单视作新的待更新工作，禁用单段重生成；同时明确失败保护禁用批次续跑，形成死锁。

1. `workbench/storyboard.py:review_state` 返回有效待更新清单：仅在原请求为 pipeline 且 `reset_applied=true` 时，扣除该请求 `redo` 中已经应用的片段。读取不写盘，保留其余新增待更新片段。
2. `workbench/jobs.py:restart` 在覆盖原请求前持久化有效审核状态，避免单段重试切换 operation、移除 redo/reset_applied 后旧标记重新生效。
3. 保留 `terminal_failed` 的显式新尝试要求以及未知提交／已接单保护；不通过清除失败任务号来绕过限制。

## 验证与交付

- 先用回归复现“已审核 + 已应用 redo + 失败片段 + 保留 dirty 清单”的刷新和接口失败，再验证多个失败片段修复后续跑完整链路。
- 验证尚未应用 redo、未包含于已应用 redo 的新增修改仍阻止生成；读取 snapshot 不改任务文件。
- 运行完整 Python / Node 离线测试、Python 编译、JS 语法和 locale 一致性检查。
- 代码与本方案使用 `fix(...)` 本地提交，永久回归使用 `test(fix):` 单独提交；清理一次性测试脚本，保留已有用户改动，不推送。
