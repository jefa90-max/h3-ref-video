# 当前分镜的场景、道具、朝向与编号

## 目标与已确认方案

用户选择先由现有文字模型生成当前镜头的具体描述，再交给图片模型。JSON 的全局 setting 只作为关键场景参考，不直接拼进图片提示词。用户补充：人物或物体背向镜头必须明确写出；提示词标明当前分镜号，方便在参考图查找关键场景；图片模型默认值改为 `gpt-image-2.6-sunburst`。

另一方案是让图片模型自行从全局资料取舍，少一次文字调用，但编辑框无法预先查看具体场景，用户未选择。采用现有 LLM_BASE_URL／LLM_MODEL／LLM_API_KEY（或 APIMart key），不增加配置、不调用 Claude。

## 数据流与约束

- `frames.describe_composition(film, shot)`：复用当前 `deepseek-v4-pro`，按当前镜头、前文及全局关键场景参考，输出 JSON `{scene, frame, orientation}`，三字段均为非空字符串。用户确认画面文字也由该模型整理；动作以 JSON 为依据，只描写镜头开始时实际可见的环境、必要道具、画面和各主体相对镜头的朝向，不提前展示未来道具或整张总表，不默认所有主体正对镜头。
- `frames.prompt(..., composition=None)` 保持无网络的纯函数。标明整片全局分镜号（素材定位用，不入画）；只有已生成的 composition 才填入具体场景与朝向，不再复制 setting。角色参考图约束外观，不能覆盖朝向。
- `film.stage_frames` 在新画图前生成 composition 并保存。成功缓存、已存在图片、已接单任务不重复调用文字模型；文字生成失败只记当前分镜失败，其他分镜继续。未知图片接单与审核拦截保持有效。
- 工作台读取与演示保持离线，显示已保存的实际提示词；手工重生成以用户编辑后的具体提示词为准，不再自动重写用户草稿。
- 本轮不自动重画已有图片、不修改视频提示词。重新打包 Windows，旧“仅移除首镜”包保留为历史文件，不作为最终交付。

## 实施与验证步骤

1. 编写离线失败用例：不复制全局 setting、背向说明、跨视频段全局分镜号、模型请求上下文与格式校验。验证旧实现失败。
2. 在 `h3ref/frames.py` 实现构图描述与提示词组装；在 `h3ref/film.py` 加入生成、缓存和单项失败边界。更新既有离线测试夹具，禁止真实联网。
3. 验证缓存复用、云端任务续查不重写、单项文字失败不阻塞整批、页面读取不调用模型、用户手改保留。运行 Python 全套、JS 全套、编译／语法与中英文键检查。临时功能测试代码完成后删除。
4. 更新说明，重新生成 Windows ZIP，核验源码／SHA256／CRC／干净解压入口，交付用户自行重启验收。
