# 本地工作台

## 启动

Windows 10/11 64 位可直接双击 `start-windows.cmd`，自动准备依赖并打开浏览器；见 [Windows 一键部署说明](windows.md)。首次需要联网，后续复用已安装环境。

在仓库根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-web.txt
python workbench.py
```

打开 http://127.0.0.1:7860。`python workbench.py --port 7862` 可换端口；同一仓库只允许一个工作台服务，换端口前先退出原服务。已有 `.venv` 时只需激活并运行最后两条命令。Windows 可用 `.venv\Scripts\python.exe`。真实出片需要 Python 3.10+、ffmpeg 和 ffprobe（macOS：`brew install ffmpeg`）。不需要 Node 或 pnpm dev。

## 不用 key 演示

1. 工作台默认选中「整条片」和「真实生成」，JSON 输入框为空；无需 key 试用时先手动切换到「离线演示」。切到「一条片段」可填写提示词、秒数（默认 12）和画幅，再启动。
2. 「整条片」可粘贴 JSON 分镜，或导入 UTF-8 编码的 `.json` / `.txt` 文件（文件内容仍需为 JSON，兼容 UTF-8 BOM）。点击「下载示例 JSON」保存无本机图片路径的范例，编辑后再导入；下载不会覆盖输入框。导入后自动列出角色图和场景／道具总表清单；逐项上传后选 shot，点击「生成分镜并审核」。也可勾选「演示时允许缺图使用占位图」来快速体验。
3. 启动后进入独立结果页 `/jobs/<任务ID>`，在「分镜图」Tab 查看分镜，每页 12 张。展开某张的提示词并单独重出，其他图片不变。
4. 浏览全部当前分镜后，点击一次「确认全部分镜并生成视频」，自动切到「视频片段」Tab。每页最多 6 段，可分别播放、下载、重生成；完整成片在下方。两类素材独立分页，手动切回分镜后不会被轮询切走。

演示媒体含 DEMO 标记，不联网、不收费，不模拟模型理解新提示词的效果。缺 ffmpeg 时仍能产出计划、图片和报告，日志会说明没有视频。

## 配置真实 key

打开「环境与密钥」，填写 `RUNNINGHUB_API_KEY` 和 `APIMART_API_KEY`，默认勾选保存到本机 `.env`，点击保存；保存后立即用于后续任务，服务重启也会沿用。不勾选则只存当前服务内存。空白 key 保持已有值，已保存的 key 不回传浏览器。`.env` 已被 git 忽略，支持 POSIX 权限的平台使用 0600；key 不写入浏览器存储或任务 JSON。也可预先按 `.env.example` 手动配置；已 export 的环境变量在启动时优先于 .env。

工作台固定 `H3_REWRITER=llm`，不探测或运行 Claude。默认 `LLM_BASE_URL=https://api.apimart.ai/v1`、`LLM_MODEL=deepseek-v4-pro`，改写使用 APIMart key；自定义 OpenAI 兼容服务可填写 LLM key / URL / model。高级的 `VISION_API_KEY`、`VISION_BASE_URL`、`H3_GUIDE_FILE` 等仍从 .env / 环境读取，手动修改后重启工作台。页面环境检查不联网鉴权或查余额，无效 key 会在实际任务中明确报错。

视频默认最多同时生成 3 段；可在 `.env` 设置 `RUNNINGHUB_CONCURRENCY`，旧文件若显式设置为 5，会继续覆盖默认值。消费级会员的网站任务也占用同一并发额度。遇到 `421 / TASK_QUEUE_MAXED`，只对明确未接单的片段每 60 秒尝试一次，最多 31 次（仅 421 累计等待最多 30 分钟）；`415` 机器资源不足仍最多尝试 5 次。两类拒绝分别计数，不因切换错误类型而重置；混合拒绝累计最多等待 34 分钟，不含接口耗时。等待耗尽后可续跑原任务，已有云端任务号继续查询；提交结果未知仍禁止自动重提。修改并发配置或更新代码不会改变正在执行的子进程，待当前任务停止后由用户重启工作台再续跑。

## 真实生成与单镜改词

1. 关闭「离线演示」。one 上传 1–9 张参考图（顺序对应参考图片编号），填写提示词、秒数、画幅，可选 seed，直接启动。字幕检查目前暂停，页面选项已禁用；已有任务即使保存了强制检查选项，也会跳过，不要求视觉模型密钥。
2. film 导入 JSON 后，页面自动列出每位角色的姓名、外观说明，以及一张场景／道具总表卡片。逐项点击上传，看到缩略图与已绑定状态后再启动；可以替换或移除。无需填写 `picture` 或本地目录，旧 JSON 的图片路径会转成待上传参考位，不会被直接使用。
3. 选 `shot`（每镜一图）或 `first`（每段首图），点击「生成分镜并审核」。默认使用 APIMart key，先调用现有文字模型（默认 `deepseek-v4-pro`）整理当前镜头，再调用图片模型（默认 `gpt-image-2.6-sunburst`）；自定义文字服务沿用 LLM key／URL／model。这一步不生成视频。`none` 没有分镜图，结果页先显示脚本计划；确认计划后才生成视频。
4. 在独立结果页的分镜卡片修改「这张图的生成提示词」。新分镜先由现有文字模型按当前镜头和前文整理场景、必要道具、画面与主体朝向，不照抄全局场景；背向镜头时明确写出人物后背／后脑勺或物体背面，提示词标明整片分镜号方便在总表中定位关键场景。结果会保存，查看页面和续查已有图片任务不重复调用文字模型；手动重生成采用编辑框里的提示词。提示词下按提交顺序展示场景／道具总表和角色图，不使用首张分镜作为参考。角色图可以移除，增加时点击「选择已导入角色」，从第一步导入本任务的角色中选择，无需重新上传；场景／道具总表只读。增删后核对提示词中的参考图片编号，点击「仅重出这张图」才会应用修改，其他分镜不变。这是图像模型提示词，直接交给原 `frames.draw`；不要把它当作视频六段式提示词编辑框。
5. 新图成功后替换该图，其他分镜不会重画；失败时保留旧图。新提交的 task 单独持久化，结果未知时续跑只查询该 task，不能用新的提示词或参考图编辑覆盖它；明确终止失败后才允许从卡片新生成，内容审核拒绝还须先手动改词。首张分镜与其他分镜相互独立，重生成不会改变其他图片的参考素材。
6. 分镜生成成功后分页检查，满意后只点一次「确认全部分镜并生成视频」。确认与启动在同一次请求中进行；若图片未齐或页面版本已过期，服务端会拒绝。改图后整片回到待确认状态，但其他分镜不重画。审核记录保存在本机，刷新、直接打开结果页或重启服务后会恢复。原仓库随后完成改写、RunningHub 视频、拼接和报告；整片和单段重生成的字幕检查目前均跳过。若是已有成片的改图任务，界面会标明旧视频/报告待更新；shot 只重做所属片段，first 从该段向后重做以延续末帧衔接。

工作台的 film 流程固定先分镜、统一确认、再出片，服务端会阻止绕过审核；CLI 命令本身仍保持原用法。实际出现的分镜受原 CLI 每段 9 张参考图预算限制，first 只审核每段首图；none 确认脚本计划。

创建页的“成果保存文件夹”可通过“选择文件夹”打开 Windows/macOS 系统目录窗口。选定后立即保存到本机 `.workbench/preferences.json`，刷新页面和重启服务均会恢复；取消选择保留原值。默认根目录为程序内的 `jobs/`。每个新任务创建 `2026-11-02_19-05-30` 这样的时间子目录，同秒冲突依次添加 `-001`、`-002`，已有文件不会覆盖。输入保存在任务子目录的 `inputs/` 内。旧任务续跑、单镜改图和继续出片始终使用该任务原目录，不受默认目录更改影响。保存的目录被移走或所在磁盘不可用时会明确报错，需要重新选择。

## 无路径 JSON 与参考位

角色只需保留 `name`、`look` 等描述，可省略 `picture`。`board: true` 表示本片必须上传一张场景／道具总表；`board: null` 或省略表示可选。旧 JSON 中非空的 board 路径导入后也会标为必需。`setting` 的描述显示在总表卡片上，多个场景／道具仍使用一张总表，不自动从自由文字拆出新图片位。

```json
{
  "cast": [{"name": "小林", "look": "灰色卫衣、圆框眼镜"}],
  "setting": "楼道与一个巨大的牛皮纸快递箱",
  "board": null,
  "shots": [{"action": "小林打开快递箱", "start": 0, "end": 5}]
}
```

上传绑定与编辑器里的故事分开保存，启动时程序写出带绝对路径的 CLI 输入副本。导入另一份 JSON 或恢复示例会清空原绑定；编辑角色名／重排角色会让对应位置重新待上传，避免串图。离线与真实模式切换保留已上传绑定；真实模式始终要求必需图片齐全。演示也可以关闭占位选项，完整验证上传流程。

`board: true` 是工作台导入标记；直接使用 CLI 时仍应按原格式提供图片路径，原 CLI 接口未更改。

## 状态、播放与恢复

创建页显示任务历史，点击记录进入独立结果页。结果页显示实际阶段、分镜审核进度、已落盘片段数、日志、报告和产物路径；100+ 分镜分页浏览，提示词按需展开。完整视频与当页片段使用本地分发的 [Plyr 3.8.5](vendor-plyr.md)，不依赖运行时 CDN；切片段页会释放离开的播放器，普通状态轮询不会重置播放进度。报告以纯文本展示。云端等待阶段可能长时间没有新日志。

分镜批次中，一张图失败或已有 task 的轮询遇到网络故障，其它图仍会继续处理，不会自动为该图新建付费 task。结果未知的图片保留原 task；用户点击「继续生成剩余分镜」只查询这些原任务，未知状态不能从卡片提交新编辑覆盖。明确终止失败后可从卡片手动重新生成；内容审核拒绝须先修改提示词。缺图或仍有未处理失败时不能确认并生成视频。

如果图片创建请求断线、没有取得 task，也会保存 `submission_unknown` 并阻止续跑或卡片重新提交。先在 APIMart 核对任务：批次记录位于 `state.json` 的 `frames`，单图编辑记录位于 `inputs/frame-edit.json`；确认任务号后补回 `task`，只有确认未接单后才清除未知标记。修改前等待本地任务停止并备份原记录。

Windows worker 显式使用 UTF-8 处理标准输入输出和文件。旧版本以系统编码写出的 `state.json` 不会自动迁移或覆盖；遇到编码错误时，先保留原文件，核对原编码和远端任务记录后再处理，避免丢失已付费任务号。

## 单段重生成与重新拼接

「视频片段」Tab 按原顺序显示每段的时间范围和分镜数量。一段是模型一次生成的 5–15 秒视频，可能包含多个分镜。点击「重新生成这一段」会沿用原提示词、分镜参考图、画幅和时长，换随机种子，仅生成目标段。真实模式只为这次片段重生成产生新的生成费用；其它片段和分镜图保持不变。one 任务仍保留原单视频结果页。

新片段成功前旧片段仍可播放；失败从原任务续跑。成功后采用新片段，旧版文件和任务记录备份在该任务 `inputs/segment-<版本>/` 下。此时完整视频和报告仍是上一版，页面标为待重新拼接。预览满意后点击「重新拼接完整视频」，只用本机 FFmpeg 按原段序拼接，不调用模型，也不要求模型 key 或原角色图片仍存在。拼接失败保留旧成片；成功才更新成片、报告和版本标记。旧成片备份位于 `inputs/previous-film-<版本>.mp4`。完整播放器下方的「下载完整视频」下载当前已拼接文件；有未应用修改时标注「旧版」，直到重新生成或拼接成功。

first / none 的上一段尾帧也是参考图，并非固定首尾帧约束。单段重生成保留后续段，需复看与下一段的接缝；这与 CLI `--redo` 会联动后续片段的行为不同。若先修改了分镜图，仍须回「分镜图」Tab 确认并应用修改，不能用重生成/拼接按钮绕过审图。

RunningHub 视频生成或单段重生成已保存云端任务号时，续跑继续查询同一任务。如果提交时断线导致是否接单未知，会阻止自动重提并在日志列出状态文件路径；此时应先在 RunningHub 核对任务，不能通过反复重试赌是否已经扣费。确认任务号后可补回对应 `state.json` 中该段的 `task`；只有确认远端未接单后，才清除 `submission_unknown` 以重新提交。修改记录前须等待本地任务停止，保留原记录备份。

一次运行一个本地任务。失败后可更新 key，再从原任务续跑；续跑使用任务已保存输入，不读取左侧新表单。改整个脚本请返回创建页新建任务，单镜改图使用结果页卡片。旧版未审核的视频任务若需要续跑，会先返回分镜阶段；已审核的新任务失败后可继续原流水线。

关闭网页不停止任务；退出服务会中断本地执行，但不保证取消已提交云端任务。服务重启后可续跑查询已记录 task；RunningHub 提交结果未知时仍会阻止重提，先按上述说明核对远端记录。源参考图被移动后，历史结果仍可查看，但缺图分镜不可重出。

`.workbench/`、默认 `jobs/` 和 `.env` 已忽略；自选其他仓库内输出目录需自行忽略。服务仅监听本机。CLI 安装和命令保持兼容，真实任务调用原 CLI / 包内 API；具体对照见 [CLI 一致性说明](workbench-cli-parity.md)。离线演示与假 API 检查不能证明真实鉴权、余额或模型效果。
