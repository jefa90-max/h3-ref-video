# 本地工作台

## 启动

Windows 10/11 64 位可直接双击 `start-windows.cmd`，自动准备依赖并打开浏览器；见 [Windows 一键部署说明](windows.md)。首次需要联网，后续复用已安装环境。

在源码目录首次使用时，先准备 Python 3.10+ 的虚拟环境。macOS 和 Linux 可运行以下命令。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-web.txt
```

Windows 使用 `python -m venv .venv` 创建环境，再运行 `.venv\Scripts\python.exe -m pip install -r requirements-web.txt`。

已安装 Node.js 和 pnpm 时，在仓库根目录运行 `pnpm dev`，打开 http://127.0.0.1:7860。脚本优先使用当前已激活的 Python 虚拟环境，未激活时使用项目的 `.venv`。`pnpm dev --port 7862 --open` 会换端口并打开浏览器。同一份源码只允许一个工作台服务，切换端口前先退出已有服务。

也可以直接用虚拟环境运行 `workbench.py`。macOS 和 Linux 使用 `.venv/bin/python workbench.py`，Windows 使用 `.venv\Scripts\python.exe workbench.py`。完整出片需要 ffmpeg 和 ffprobe，macOS 可通过 `brew install ffmpeg` 安装。

## 不用 key 演示

1. 工作台默认选中「整条片」和「真实生成」，JSON 输入框为空；无需 key 试用时先手动切换到「离线演示」。切到「一条片段」可填写提示词、秒数（默认 12）和画幅，再启动。
2. 「整条片」可粘贴 JSON 分镜，或导入 UTF-8 编码的 `.json` / `.txt` 文件（文件内容仍需为 JSON，兼容 UTF-8 BOM）。点击「下载示例 JSON」保存无本机图片路径的范例，编辑后再导入；下载不会覆盖输入框。导入后自动列出角色图和场景／道具总表清单；逐项上传后选 shot，点击「生成分镜并审核」。也可勾选「演示时允许缺图使用占位图」来快速体验。
3. 启动后进入独立结果页 `/jobs/<任务ID>`，在「分镜图」Tab 查看分镜，每页 12 张（也可切换到「大图」视图并用 `←` / `→` 方向键逐张浏览）。展开某张的提示词并单独重出，其他图片不变。
4. 浏览全部当前分镜后，点击一次「确认全部分镜并生成视频」，自动切到「视频片段」Tab。每页最多 6 段，可分别播放、下载、重生成；完整成片在下方。两类素材独立分页，手动切回分镜后不会被轮询切走。

演示媒体含 DEMO 标记，不联网、不收费，不模拟模型理解新提示词的效果。缺 ffmpeg 时仍能产出计划、图片和报告，日志会说明没有视频。

## 配置真实 key

打开「环境与密钥」，选择视频生成后端（`ComfyUI` 或 `RunningHub`）并填写对应参数与 `APIMART_API_KEY`，默认勾选保存到本机 `.env`，点击保存；保存后立即用于后续任务，服务重启也会沿用。选择 `ComfyUI` 时填写 `COMFYUI_URL`（支持英文逗号或换行填写多节点并发）、`COMFYUI_API_KEY`（公网 HTTPS 隧道必填，本机 HTTP 可留空）及可选的 `COMFYUI_CONCURRENCY`、`COMFYUI_PRESET`（默认 `full20`，可选 `8step` / `4step`）、`COMFYUI_RESOLUTION`（默认 `768p`，可选 `544p`）、`COMFYUI_UPSCALE`（默认关闭）、`COLAB_GPU`（默认 `G4`，可选 `A100` / `H100`）、`COLAB_AUTO_START`（默认关闭）；页面顶部提供 ComfyUI / Colab 运行状态卡片用于只读探活、按需一键启动主节点及第 2 节点、确认 Google Drive 授权与带在途保护的终止实例。选择 `RunningHub` 时填写 `RUNNINGHUB_API_KEY`。不勾选保存则只存当前服务内存。空白 key 保持已有值，已保存的 key 不回传浏览器。`.env` 已被 git 忽略，支持 POSIX 权限的平台使用 0600；key 不写入浏览器存储或任务 JSON。也可预先按 `.env.example` 手动配置；已 export 的环境变量在启动时优先于 .env。

工作台固定 `H3_REWRITER=llm`，不探测或运行 Claude。选择「文字模型服务」后，分别填写「构图规划模型」和「提示词改写模型」的模型 ID，两项可不同；保存后用于新启动的任务，已有模型产物继续复用，正在运行的子进程不变。

- **APIMart / 自定义兼容服务**：默认地址 `https://api.apimart.ai/v1` 时，文字密钥优先使用 `LLM_API_KEY`，否则回退 `APIMART_API_KEY`。两项模型分别保存到 `LLM_COMPOSITION_MODEL` / `LLM_REWRITE_MODEL`；旧 `LLM_MODEL` 继续作为未单独配置时的默认值，缺省为 `deepseek-v4-pro`。改为非 APIMart 自定义地址时必须单独填写 `LLM_API_KEY`（不回退 `APIMART_API_KEY`，切换地址来源会清空未重填的旧 `LLM_API_KEY`）。
- **Gemini 官方**：选择后填写 `GEMINI_API_KEY`，固定调用 `https://generativelanguage.googleapis.com/v1beta/openai/`。两项模型分别保存到 `GEMINI_COMPOSITION_MODEL` / `GEMINI_REWRITE_MODEL`；未单独配置时沿用 `GEMINI_MODEL`，缺省为 `gemini-flash-latest`。不使用遗留的 APIMart / LLM key、地址或模型，也不自动切换至 APIMart。

两个平台已保存的模型设置互不覆盖，切换时也暂存当前表单输入；点击保存只应用当前所选平台的表单设置。分镜图片仍由 APIMart 生成，使用 Gemini 规划后出图也需要 `APIMART_API_KEY`。高级的 `VISION_API_KEY`、`VISION_BASE_URL`、`H3_GUIDE_FILE` 等仍从 .env / 环境读取，手动修改后重启工作台。页面环境检查不联网鉴权或查余额，无效 key 会在实际任务中明确报错。

ComfyUI 模式默认并发等于已配置节点数（每节点同时 1 段，可在环境配置或 `.env` 中通过 `COMFYUI_CONCURRENCY` 显式覆盖）。RunningHub 模式视频默认最多同时生成 3 段；可在 `.env` 设置 `RUNNINGHUB_CONCURRENCY`，旧文件若显式设置为 5，会继续覆盖默认值。消费级会员的网站任务也占用同一并发额度。遇到 `421 / TASK_QUEUE_MAXED`，只对明确未接单的片段每 60 秒尝试一次，最多 31 次（仅 421 累计等待最多 30 分钟）；`415` 机器资源不足仍最多尝试 5 次。两类拒绝分别计数，不因切换错误类型而重置；混合拒绝累计最多等待 34 分钟，不含接口耗时。等待耗尽后可续跑原任务，已有云端任务号继续查询；提交结果未知仍禁止自动重提。修改并发配置或更新代码不会改变正在执行的子进程，待当前任务停止后由用户重启工作台再续跑。

## 真实生成与单镜改词

1. 关闭「离线演示」。one 上传 1–9 张参考图（顺序对应参考图片编号），填写提示词、秒数、画幅，可选 seed，直接启动。字幕检查目前暂停，页面选项已禁用；已有任务即使保存了强制检查选项，也会跳过，不要求视觉模型密钥。
2. film 导入 JSON 后，页面自动列出每位角色的姓名、外观说明，以及一张场景／道具总表卡片。当角色数 ≥ 2 时，可勾选多个角色卡片合并为一张「多角色合图」卡片共用一次上传（随时可「拆开单独上传」），使多角色剧本控制在模型最多 9 张参考图的上限内；提示词层会自动标注合图内各出场角色的外观特征以防串脸，并禁止同图未出场角色乱入。逐项点击上传，看到缩略图与已绑定状态后再启动；可以替换或移除。无需填写 `picture` 或本地目录，旧 JSON 的图片路径会转成待上传参考位，不会被直接使用。
3. 选 `shot`（每镜一图）或 `first`（每段首图），按需保留默认勾选的「使用文字模型精简优化分镜提示词」（也可取消勾选以直接使用原始剧本分镜词生图，对应 CLI `--no-optimize-storyboard`），点击「生成分镜并审核」。开启优化时，先按所选文字服务调用构图规划模型（APIMart 默认 `deepseek-v4-pro`，Gemini 默认 `gemini-flash-latest`）输出精简的 `composition v3`（机位构图、场景陈设、人物左中右站位与程序级跨镜头逐字锁定的 `locked_look` 外貌词）；若文字模型返回空或格式校验失败，自动附带错误摘要重试最多 3 次，仍未通过则自动回退原始剧本分镜词继续生图（401/402/403/404/429 立即停止报错）。再用 `APIMART_API_KEY` 调用图片模型（默认 `gpt-image-2.6-sunburst`）出图；这一步不生成视频。`none` 没有分镜图，优化复选框自动禁用，结果页先显示脚本计划；确认计划后才生成视频。
4. 在独立结果页的分镜卡片修改「这张图的生成提示词」。新分镜先由现有文字模型按当前镜头和前文整理场景、必要道具、画面与主体朝向，不照抄全局场景；背向镜头时明确写出人物后背／后脑勺或物体背面，提示词标明整片分镜号方便在总表中定位关键场景。结果会保存，查看页面和续查已有图片任务不重复调用文字模型；手动重生成采用编辑框里的提示词。提示词下按提交顺序展示场景／道具总表和角色图，不使用首张分镜作为参考。角色图可以移除，增加时点击「选择已导入角色」，从第一步导入本任务的角色／合图中选择，无需重新上传；场景／道具总表只读。增删后核对提示词中的参考图片编号，点击「仅重出这张图」才会应用修改，其他分镜不变。这是图像模型提示词，直接交给原 `frames.draw`；不要把它当作视频六段式提示词编辑框。
5. 新图成功后替换该图，其他分镜不会重画；失败时保留旧图。新提交的 task 单独持久化，结果未知时续跑只查询该 task，不能用新的提示词或参考图编辑覆盖它；明确终止失败后才允许从卡片新生成，内容审核拒绝还须先手动改词。首张分镜与其他分镜相互独立，重生成不会改变其他图片的参考素材。
6. 分镜生成成功后分页检查，满意后只点一次「确认全部分镜并生成视频」。确认与启动在同一次请求中进行；若图片未齐或页面版本已过期，服务端会拒绝。改图后整片回到待确认状态，但其他分镜不重画。审核记录保存在本机，刷新、直接打开结果页或重启服务后会恢复。原仓库随后完成改写、所选视频后端（ComfyUI / RunningHub）出片、拼接和报告；整片和单段重生成的字幕检查目前均跳过。若是已有成片的改图任务，界面会标明旧视频/报告待更新；shot 只重做所属片段，first 从该段向后重做以延续末帧衔接。

工作台的 film 流程固定先分镜、统一确认、再出片，服务端会阻止绕过审核；CLI 命令本身仍保持原用法。实际出现的分镜受原 CLI 每段 9 张参考图预算限制，first 只审核每段首图；none 确认脚本计划。

创建页的“成果保存文件夹”可通过“选择文件夹”打开 Windows/macOS 系统目录窗口。选定后立即保存到本机 `.workbench/preferences.json`，刷新页面和重启服务均会恢复；取消选择保留原值。默认根目录为程序内的 `jobs/`。每个新任务创建 `2026-11-02_19-05-30` 这样的时间子目录，同秒冲突依次添加 `-001`、`-002`，已有文件不会覆盖。输入保存在任务子目录的 `inputs/` 内。旧任务续跑、单镜改图和继续出片始终使用该任务原目录，不受默认目录更改影响。保存的目录被移走或所在磁盘不可用时会明确报错，需要重新选择。

## 无路径 JSON 与参考位

角色只需保留 `name`、`look` 等描述，可省略 `picture`。`board: true` 表示本片必须上传一张场景／道具总表；`board: null` 或省略表示可选。旧 JSON 中非空的 board 路径导入后也会标为必需。`setting` 的描述显示在总表卡片上，多个场景／道具仍使用一张总表，不自动从自由文字拆出新图片位。

```json
{
  "cast": [{"name": "小林", "look": "灰色卫衣、圆框眼镜"}],
  "setting": "楼道与一个巨大的牛皮纸快递箱",
  "board": null,
  "shots": [{"action": "小林打开快递箱", "start": 0, "end": 5}]
}
```

上传绑定与编辑器里的故事分开保存，启动时程序写出带绝对路径的 CLI 输入副本。导入另一份 JSON 或恢复示例会清空原绑定；编辑角色名／重排角色会让对应位置重新待上传，避免串图。离线与真实模式切换保留已上传绑定；真实模式始终要求必需图片齐全。演示也可以关闭占位选项，完整验证上传流程。

`board: true` 是工作台导入标记；直接使用 CLI 时仍应按原格式提供图片路径，原 CLI 接口未更改。

## 台词语速预检

创建页解析剧本后会自动给出预算提示。先看风险较高的镜头，用「定位到脚本」选中原始台词。补填 `speech`、精简台词或调整生成预算后，页面会重新估算。提示不会修改 JSON，也不会拦住任务。估算按镜头时长、语速档和停顿计算，有效镜长最多取 15 秒。实际口播还受分段取整和开场停顿影响，默认阈值仍待实片校准。

```bash
python h3ref.py preflight --film examples/dialogue-budget.json --json
```

示例的 JSON 关键字段如下，实际输出还包含镜头号、预算、台词预览、详细计数和配置指纹。

```json
{
  "status": "partial",
  "warnings": [
    {"code": "dialogue_over_budget", "shot": 2, "raw_shot_index": 1},
    {"code": "dialogue_slow_over_budget", "shot": 3, "raw_shot_index": 2}
  ],
  "meta": {"calibration_status": "provisional", "checked_shots": 3, "skipped_shots": 1}
}
```

省略 `--json` 可读人类摘要，`--film -` 从标准输入读取最多 32 MiB。退出码 `0` 表示命令产生了结果，`1` 表示文件、JSON 或阈值配置有误，`2` 表示启用 `--fail-on-warn` 后有告警或状态不为 `complete`。命令从环境变量读取 `H3_LANG` 和可选的 `H3_DIALOGUE_RATE_CONFIG`，无需加载 `.env`、生成服务或参考素材。原始时间戳的有效范围为 0–3600 秒。起止时间任一缺失或无效时，预检按默认 2 秒估算，并将该镜计入 `default_duration_shots`。旧 CLI 剧本若用了绝对时间，可减去共同起点。在所有时间戳都落入有效范围时，镜长保持相同。

| 告警 | 建议 |
|---|---|
| `dialogue_over_budget` / `dialogue_slow_over_budget` | 精简台词，或拆成总有效生成预算足够的多段，单段上限仍为 15 秒。 |
| `dialogue_long_line` | 台词偏长，可按表达节奏拆镜。 |
| `dialogue_speech_unset` | 补充台词语言，如 `"speech": "zh"`。 |
| `dialogue_unsupported_script` | 该镜文字暂无法估算，需人工核对。 |
| `dialogue_shots_invalid` | 将 `film.shots` 改为镜头数组。 |

`complete` 表示检查覆盖完整，可包含告警。`partial` 表示使用了默认时长、略过镜头或缺少检查所需信息。`unsupported` 表示有台词文字暂不支持计数，且没有可估算的台词。`invalid` 表示缺少可检查的镜头数组。草稿中缺失 `shots` 或给出 `null` 时，参考图接口仍可返回上传位。

对于已经运行的本地工作台，同一份脚本可直接调用接口。

```bash
jq '{film: .}' examples/dialogue-budget.json | curl -sS \
  -H 'X-Workbench: 1' -H 'Accept-Language: en' -H 'Content-Type: application/json' \
  --data-binary @- http://127.0.0.1:7860/api/film/references
```

示例返回 `film`、`slots`、英文 `warnings[].message`、`preflight_status: "partial"` 和 `preflight_meta`。失败响应使用 `application/problem+json`，包含 `code`、`fix` 和兼容字段 `error`。

需要自定义语速时，`H3_DIALOGUE_RATE_CONFIG` 支持内联 JSON 或不超过 64 KiB 的普通 JSON 文件。覆盖项按 `chars` / `words` 分组，可分别指定 `regular_rate`、`slow_rate`、`long_line_limit`，例如 `{"chars":{"regular_rate":6.5}}`。`H3_SKIP_PREFLIGHT=1` 可关闭自动任务的预检。显式 CLI 检查和创建页的参考图请求仍会运行。覆盖配置无效时，CLI 返回配置错误，工作台显示提醒并使用默认阈值。

开启自动预检时，新整片任务把检查时的阈值指纹和结果存进 `inputs/preflight.json`。CLI 任务的源剧本变更后，会为当前剧本重新估算，并保留创建时快照。历史任务缺少快照且重算发现告警或检查不完整时，报告会标出 `provenance_unknown` 和重算指纹。升级后的续跑仍可复用匹配的提示词和分镜图缓存。重新改写、重生成或补跑尚未完成的步骤可能触发相应的模型调用和费用。

## 状态、播放与恢复

创建页显示任务历史，点击记录进入独立结果页。结果页显示实际阶段、ComfyUI 实时推理进度（阶段、采样步数、显存与节点）、分镜审核进度、已落盘片段数、日志、报告和产物路径；100+ 分镜分页浏览，提示词按需展开。完整视频与当页片段使用本地分发的 [Plyr 3.8.5](vendor-plyr.md)，不依赖运行时 CDN；切片段页会释放离开的播放器，普通状态轮询不会重置播放进度。报告以纯文本展示。云端等待阶段可能长时间没有新日志。

分镜批次中，一张图失败或已有 task 的轮询遇到网络故障，其它图仍会继续处理，不会自动为该图新建付费 task。结果未知的图片保留原 task；用户点击「继续生成剩余分镜」只查询这些原任务，未知状态不能从卡片提交新编辑覆盖。明确终止失败后可从卡片手动重新生成；内容审核拒绝须先修改提示词。缺图或仍有未处理失败时不能确认并生成视频。

如果图片创建请求断线、没有取得 task，也会保存 `submission_unknown` 并阻止续跑或卡片重新提交。先在 APIMart 核对任务：批次记录位于 `state.json` 的 `frames`，单图编辑记录位于 `inputs/frame-edit.json`；确认任务号后补回 `task`，只有确认未接单后才清除未知标记。修改前等待本地任务停止并备份原记录。

Windows worker 显式使用 UTF-8 处理标准输入输出和文件。旧版本以系统编码写出的 `state.json` 不会自动迁移或覆盖；遇到编码错误时，先保留原文件，核对原编码和远端任务记录后再处理，避免丢失已付费任务号。

## 单段重生成与重新拼接

「视频片段」Tab 按原顺序显示每段的时间范围和分镜数量。一段是模型一次生成的 5–15 秒视频，可能包含多个分镜。点击「重新生成这一段」会沿用原提示词、分镜参考图、画幅和时长，换随机种子，仅生成目标段。真实模式只为这次片段重生成产生新的生成费用；其它片段和分镜图保持不变。one 任务仍保留原单视频结果页。

新片段成功前旧片段仍可播放；失败从原任务续跑。成功后采用新片段，旧版文件和任务记录备份在该任务 `inputs/segment-<版本>/` 下。此时完整视频和报告仍是上一版，页面标为待重新拼接。预览满意后点击「重新拼接完整视频」，只用本机 FFmpeg 按原段序拼接，不调用模型，也不要求模型 key 或原角色图片仍存在。拼接失败保留旧成片；成功才更新成片、报告和版本标记。旧成片备份位于 `inputs/previous-film-<版本>.mp4`。完整播放器下方的「下载完整视频」下载当前已拼接文件；有未应用修改时标注「旧版」，直到重新生成或拼接成功。

first / none 的上一段尾帧也是参考图，并非固定首尾帧约束。单段重生成保留后续段，需复看与下一段的接缝；这与 CLI `--redo` 会联动后续片段的行为不同。若先修改了分镜图，受影响片段及完整拼接仍须回「分镜图」Tab 确认并应用修改（未受影响片段仍可单独重生成），不能绕过审图。

视频生成或单段重生成已保存云端任务号时，续跑按任务记录的 `provider` 继续查询同一任务（ComfyUI 同时按该段记录的 `comfyui_url` 与密钥指纹回查；若远端实例重启导致任务连续两次既不在 `/history` 也不在 `/queue`，会快速判定为终态失败）。如果提交时断线导致是否接单未知，会阻止自动重提并在日志列出状态文件路径；此时应先在对应后端（RunningHub 或 ComfyUI）核对任务，不能通过反复重试赌是否已经扣费。确认任务号后可补回对应 `state.json` 中该段的 `task`；只有确认远端未接单后，才清除 `submission_unknown` 以重新提交。修改记录前须等待本地任务停止，保留原记录备份。

一次运行一个本地任务。失败后可更新 key，再从原任务续跑；续跑使用任务已保存输入，不读取左侧新表单。改整个脚本请返回创建页新建任务，单镜改图使用结果页卡片。旧版未审核的视频任务若需要续跑，会先返回分镜阶段；已审核的新任务失败后可继续原流水线。

关闭网页不停止任务；退出服务会中断本地执行，但不保证取消已提交云端任务。服务重启后可续跑查询已记录 task；视频后端（ComfyUI / RunningHub）提交结果未知时仍会阻止重提，先按上述说明核对远端记录。源参考图被移动后，历史结果仍可查看，但缺图分镜不可重出。

`.workbench/`、默认 `jobs/` 和 `.env` 已忽略；自选其他仓库内输出目录需自行忽略。服务仅监听本机。CLI 安装和命令保持兼容，真实任务调用原 CLI / 包内 API；具体对照见 [CLI 一致性说明](workbench-cli-parity.md)。离线演示与假 API 检查不能证明真实鉴权、余额或模型效果。

## 单首帧调度与兼容

仍是一镜一张首帧，不生成尾图，不引用其它生成分镜。新镜默认采用精简的 `composition v3`（机位与构图、当前场景陈设、人物左中右站位及本镜首帧姿态），渲染为中文剧照描述并同步精简下游视频中文提示词。程序通过 `locked_look` 保持固定外貌一致，临时持物、姿势及剧本明确摘下或脱下的物件按当前镜头处理。历史任务已落盘的 `composition v2` 缓存继续兼容读取。

规划顺序执行，每镜落盘后立即并行画图；构图调用遇到空返回或 JSON／字段校验不通过时最多重试 3 次，仍失败则回退原始分镜词继续出图，鉴权／欠费／限流／模型不存在（401/402/403/404/429）立即中止。也可在创建页取消勾选优化开关（或 CLI 传 `--no-optimize-storyboard`）跳过构图模型，此时仅生成分镜图无需配置文字模型密钥。单镜图片生成失败仍不妨碍其它镜头，CLI 以 FRAME_BATCH_INCOMPLETE 非零退出并指明 state.json。

旧图片、三字段缓存、`v2` 缓存、已接单及提交未知任务沿用原记录，不自动迁移或重新付费。手改图片文字或参考顺序／文件版本后保留原 composition 追溯，但失配状态不再进入视频或后续规划；人工同时核对后续镜头。创建校验、结果页单镜角色图增删、图片提交与视频分段均按路径去重并统一限制总参考图 ≤ 9 张；结果页对合图统一显示为 `角色A / 角色B`。没有自动视觉验收；离线测试不能证明真实图像连续性。

## 视频片段提示词

在「视频片段」卡片展开「查看或编辑此段提示词」。默认编辑源词；可明确切到实际 H3 六段式。切换不会自动翻译或转换，两种格式各保留一份草稿。H3 改写自动剥离 `<think>` 思考块与外层代码围栏，强制校验六段齐全且每段非空，遇到空返回或格式／图片引用越界时最多附带具体错误重试 6 次（共最多 7 次请求），缺少本地 `claude` 或遇到不可重试状态码（400/401/402/403/404/405/413/422/429）立即终止。

历史任务支持**不触发视频生成（ComfyUI / RunningHub）扣费、仅重新转化并预览英文提示词**：
- 单段卡片编辑区内点击「重新转化为英文提示词 · 付费」（离线演示为「生成演示英文提示词」，`POST /api/jobs/<id>/segments/<number>/rewrite`），仅校验文字模型密钥与静态／分镜参考图，落盘更新 `state.json` 与 `prompts/segN.{zh,h3}.txt`，保留已有 `segN.mp4` 不变（若已有视频，会保存 `clip_prompts` 快照使「当前视频使用的提示词」继续显示上一版视频所用词，并在卡片标注新英文词尚未应用到视频），完成后编辑器自动切至 `h3` 视图供检查；之后点击「重新生成这一段」会自动命中 `reuse_h3` 直接生成视频，无需二次改写付费。
- 面板顶部支持「补齐未转化英文提示词 · 付费」（`scope: "missing"`）与「全部重新转化为英文提示词 · 付费」（`scope: "all"`，`POST /api/jobs/<id>/segments/rewrite`，离线演示无「· 付费」后缀）；即使部分片段尚无 `mp4` 视频文件也可查看与预改写，未完结历史任务在改写完成后仍可直接点击「续跑」衔接原视频流水线。

编辑、展开、查看当前视频提示词、切页、切 Tab、语言切换和轮询均不调用模型。按「仅重新生成这一段」才提交所选格式；源词变化或参考来源变化可能先产生文字改写费用，再产生视频费用；原词且配对缓存有效或直接 H3 只需目标段视频费用。离线演示不请求模型、不冒充真实改写结果（手动转化英文提示词时仅在本地生成带 DEMO 标记的六段式预览模板）。新片成功前旧片和旧成片仍可播放，成功后仍须手动拼接。

编辑框优先保留上次失败尝试的文字；「当前视频使用的提示词」另行显示生效的源词/H3，失败文字不代表旧视频所用文字。每段、每种格式的草稿跨轮询、分页、Tab 与语言切换保留；刷新页面会丢弃未提交的内存草稿，请自行复制重要草稿。后台或另一标签页更新版本后，保留草稿并禁止覆盖；复核当前生效词，再明确点击「以当前版本使用此草稿」。提交成功只清理匹配 revision、文字和格式且未继续修改的那一份。

参考清单只读，按**本次重生成**的真实上传顺序编号。九图裁减会明确提示省略总表或后部镜头；旧视频若没保存历史顺序，不将此清单声称为历史输入。分镜或参考素材变化后，手改视频词仍保留并提示复核；原审图门禁、dirty_segments 和任务互斥继续生效。

## 视频提示词错误与恢复

| 当前尝试 | 可用动作 | 费用与已有成果 |
| --- | --- | --- |
| 未改写的 source | 核对配置后继续，或修词新建尝试 | 需要文字 key；已经完成的文字请求可能收费 |
| 已保存 H3、视频尚未接单 | 恢复相同尝试 | 复用改写缓存；明确拒单仍沿原有限重试策略 |
| 已有未决 task | 全局「续跑」恢复原 task | 不重新上传、改写或提交；禁止用新词覆盖 |
| submission_unknown 且无 task | 在供应商后台核对，恢复原任务号 | 禁止重复生成；响应丢失可能已收费 |
| 明确终态失败 | 修词后点击卡片「用当前提示词再次生成此段」 | 创建新 revision，产生新费用；全局续跑不会自动再付费 |
| 发布中断 | 续跑完成发布 | 只发布本次已生成文件，不再改写／上传／提交 |
| 发布成功、成片待更新 | 手动重新拼接 | 不调用生成模型；旧成片在拼接成功前保留 |

视频、尾帧、本段 `.zh.txt`/`.h3.txt` 和 active 记录以 `segment-edit.json` 的 `applied` 为共同可见提交点。发布前读取旧组，提交后读取新组；旧媒体 URL 带 `v` 时只返回对应字节，无法匹配则 404，不默默换成新版。未提交发布期间禁止拼接或 CLI pipeline 消费混版根文件，先在工作台续跑发布；工作台子进程运行中或存在未决的单图／单段任务时，CLI `film` 同样会拒绝并发执行。

扩展接口仍是 `POST /api/jobs/<id>/segments/<number>/regenerate`。新客户端提交 `version`、`prompt_version`、`prompt`、`prompt_format`；前两项来自开始编辑时的 GET 快照。旧 `{version}` 请求仍可在有视频、有有效提示词且没有未决尝试时沿用换种子行为。无视频的终态失败项使用新版本契约修复。

以下仅示范协议，**真实 POST 会生成并计费**；本次开发未执行这些付费请求。将示例版本替换为 GET 中相应段的版本，不要覆盖已编辑草稿的基线。

源词示例：

```bash
curl -H 'X-Workbench: 1' -H 'Accept-Language: zh-CN' \
  'http://127.0.0.1:7860/api/jobs/JOB_ID'
# 读取 segments[1].version 和 segments[1].prompt_version，然后使用源词：
curl -X POST -H 'X-Workbench: 1' -H 'Accept-Language: zh-CN' \
  -H 'Content-Type: application/json' \
  'http://127.0.0.1:7860/api/jobs/JOB_ID/segments/2/regenerate' \
  --data '{"version":"GET中的视频版本","prompt_version":"开始编辑时的提示词版本","prompt":"按当前机位，接收者跪地侧身托袋。","prompt_format":"source"}'
```

直接 H3 示例（不需要文字改写 key，仍需视频 key；每个 Picture 引用必须匹配本次实际参考数）：

```bash
curl -H 'X-Workbench: 1' -H 'Accept-Language: en' \
  'http://127.0.0.1:7860/api/jobs/JOB_ID'
# 重新读取相应段版本；此示例没有 Picture 引用，实际脚本应保留自己的全部镜头和台词：
curl -X POST -H 'X-Workbench: 1' -H 'Accept-Language: en' \
  -H 'Content-Type: application/json' \
  'http://127.0.0.1:7860/api/jobs/JOB_ID/segments/2/regenerate' \
  --data '{"version":"CLIP_VERSION_FROM_GET","prompt_version":"PROMPT_VERSION_AT_EDIT_START","prompt":"subject_definitions:\n<Subject 1> The recipient.\n\nsummary:\nA careful handover.\n\nretention_analysis:\nThe recipient keeps the same clothing.\n\ndetailed_description:\n[Shot 1] The recipient kneels beside the counter and supports the upright bag.\n\noverall_soundscape:\nFabric rustles.\n\nnon_diegetic_music:\nN/A","prompt_format":"h3"}'
```

校验与冲突沿用 HTTP 400，任务不存在 404，意外本地异常 500。此 POST 及单段／批量提示词转化接口（`/rewrite`）均返回 `application/problem+json`：`type=urn:workbench:error:<code>`、`title/status/detail/code/doc_anchor`，字段问题带 `field`，意外异常带 `instance` 关联本地脱敏日志；兼容保留 `error=detail`。异步改写／生成失败保存在对应片段 `error/attempt_error`，包含阶段、revision、恢复动作和费用副作用，不将 POST 接收成功当作视频已成功。

升级前先停下正在运行的任务并备份任务输出目录（尤其 `state.json`、`inputs/`、`clips/`、`prompts/`）。旧任务不会自动迁移或重新规划。Python 和语言 JSON 已修改，**请自行重启工作台**后体验；本次没有启动或重启服务。

单段修复完成后，若原整片仍有未决任务或未开始片段，全局「续跑」会继续原整片范围：已接单段只轮询原 task，完成段不重画、不重生成，未开始段按原计划继续。终态失败和未知接单仍各自受门禁保护。原词的旧 `{version}` 请求只复用旧 H3，不增加文字改写；未改源词也不会被自动标成手改覆盖。

`prompt_version` 包含本段当前实际有序参考版本；参考变更后旧草稿必须复核。新增 `source_rewrite_required` 是后端共享缓存判定，前端以它及实际草稿差异显示费用，单纯“源输入待复核”不会被误算成必需文字改写。first/none 的来源标记在首次实际上传引用时绑定，避免把尚未生成的前段尾帧当作已用素材。媒体响应先打开并校验文件描述符再发送；快照遇到发布变化会重试，保证提示词与媒体属于同一可见版本。
