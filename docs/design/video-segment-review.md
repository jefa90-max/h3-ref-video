# 视频片段预览、单段重生成与重新拼接

日期：2026-11-02。状态：用户已确认；结果页采用分镜图 / 视频片段两个并列 Tab，开始生成视频后自动切到视频片段。

## 用户目标与建议边界

用户要求：整条视频生成后，能够看到每一段视频；不满意时只重新生成其中一段；之后可以重新拼接完整视频。

第一版建议按现有 film 切段工作：一段是模型一次生成的 5–15 秒视频，可能包含多个分镜。没有独立视频的单个分镜不另做切割或重新划段。首次“确认全部并生成视频”保持现有自动生成并拼接的行为，新增操作用于后续审片和修改。

以下产品选择已由用户确认：

- 单段重生成沿用当前分镜图、原视频提示词、时长、画幅，换随机种子；本轮不增加视频提示词编辑器。
- 所有模式都严格只生成选中的片段。first / none 使用前一段尾帧；替换某段后保留后续片段，并提示检查下一段接缝。用户若不满意，可再单独重生成下一段。
- 新片段成功后采用新片段，保留上一版文件备份；第一版不扩展为多版本选择器。
- 片段重生成与重新拼接是两个明确动作，重生成完成后不会自动改动当前完整视频。

### 首尾帧语义核实

用户追问固定首尾帧是否能避免替换后的接缝变化。核对实际提交图后确认：当前使用 MiniMaxH3ReferenceToVideo，图片输入是 ref_images.ref_image_0 至 ref_image_8，没有分别固定片段首帧和尾帧的输入。shot 的分镜图，以及 first / none 的前段尾帧，均作为参考图传入；提示词描述它们的用途，不等同于硬性锁定视频端点。segN-last.jpg 是该段生成后提取的输出，不是预先指定的该段终点。

因此不能承诺只换种子仍保持相同首尾画面。若后续希望改成真正固定首尾帧的生成，需单独确认模型和工作流支持；本设计不据此假设已消除接缝问题。即便端点图固定，也仍需检查动作速度和声音的衔接。

## 页面与流程

独立结果页使用并列的“分镜图”和“视频片段”两个 Tab。审图阶段默认分镜图，视频生成开始后自动切换到视频片段；用户随后手动切回时，轮询不得强行切走。刷新已有视频或正在生成视频的任务默认视频片段。Tab 支持键盘操作和 aria-selected / aria-controls，隐藏面板不继续播放视频。

视频片段 Tab 按脚本顺序显示段号、脚本时间范围、覆盖分镜数、状态、播放/下载入口、“重新生成这一段”，并容纳完整视频及重新拼接入口。片段分页，每页最多 6 段，沿用本地 Plyr；切页销毁离开的播放器，状态轮询不重建文件未变且正在播放的播放器。one 任务保留原完整播放器，不显示两个 film 专用 Tab。

已有任务直接从保存的计划和片段文件读取，缺失片段显示未生成。分镜图和视频片段各自分页。

重生成过程中显示目标段进度，旧片段仍可播放。成功后更新该卡片；完整视频继续播放上一版，标注“有片段已更新，待重新拼接”。失败显示错误和续跑入口。真实模式的按钮说明会产生新一次生成费用；尾帧依赖提示只在相关模式和非末段出现。

提供单独的“重新拼接完整视频”按钮，按原始段序使用所有当前片段。缺段、分镜变化尚未应用到片段、当前任务运行中时禁用，并由后端再次校验。拼接成功后更新完整播放器、报告与版本状态。

## 状态与失败恢复

重生成前验证片段号、已完成任务状态、审图确认、目标参考图及前段尾帧。分镜已改但尚未确认应用的视频继续走已有审图更新流程，不能通过新按钮绕过。

新生成记录与生效片段分开保存；获得云端任务号后立即持久化。新视频和尾帧先写入临时位置，成功后才替换当前片段与状态，原片段保留备份。断线续跑使用已知任务号，只有明确终态失败后才允许再次提交。替换步骤记录应用进度，进程中断恢复不会重复生成或重复计费。

片段成功替换后标记成片待拼接，原成片仍可播放。分别表达分镜变化待生成、片段操作执行中或失败、片段齐全但成片待拼接。

拼接先输出临时 MP4，验证可读后再替换成片；FFmpeg 失败不损坏原成片。记录本次使用的片段版本，成功后才清理待拼接标记；恢复时也核对输入版本。

沿用报告的当前片段费用口径，不能把当前版本的费用称为累计历史花费。保留恢复所需的旧任务记录，本轮不扩展成本分析功能。
