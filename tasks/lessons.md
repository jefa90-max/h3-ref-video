# 项目协作经验

- 2026-11-09：用户将「改计划后立即编码」更正为「只更新计划、本地提交、然后停下」。收到撤回实施授权后，立即把计划和 todo 的当前边界同步为文档交付；即使消息附带 autoplan 技能，也要按“清空会话后再运行”的明确时序执行，不能当作本轮启动评审或恢复编码的授权。

- 2026-11-09：用户要求回到一镜一张首帧，并补充角色描述必须逐镜变化。后续连续性方案先区分稳定身份外观与当前镜头的动作、位置、身体朝向和视线；不能原样复用整段 cast.look，把持物、姿势或道具位置也锁成全片常量。首尾帧试验仅作证据，不自动升级为正式路线。

- 2026-11-08：分镜图片提示词不能照抄全局场景／关键道具，须先按当前镜头与前文写具体场景，关键场景仅作参考；人物或物体的背向必须明确描述，角色正面参考不能覆盖镜头朝向；提示词写整片全局分镜号方便匹配参考图，并注明编号不入画。文字描述应缓存，恢复已提交任务不得重复改写／付费。

- 2026-11-08：用户要求移除图片生成的首镜参考图，并再次强调提示词也不能引用首镜。此类参考图删除需同时检查实际提交图片、自动提示词、旧任务保存的提示词／待提交重生成请求、页面展示与多语言说明；不能只删图片列表。已接单任务保留原任务号续查，不为清理旧提示词重新付费。

- 2026-11-08：消费级 Key 日志中 3 段已接单、另 2 段返回 421，不能解释为只能串行。并发默认值按当前权益保守设置，同时保留环境变量覆盖；421 排队等待需覆盖前一批视频运行时间，不能沿用机器不足的短预算。降低默认值不足以处理旧 .env=5 或网站占位，需保留有界等待与未知提交保护。

- 2026-11-08：用户指出 RunningHub 仍有付费会员积分，并提供企业共享 Key 类型与钱包 ¥0 截图。遇到 605 等余额报错，先核对 Key 类型、个人／团队主体、会员积分与钱包以及 API 可用额度，不能把拒单直接解释为账户总积分耗尽或直接建议充值。会员体系变更时核对官方新旧权益与实际套餐，不能保证所有会员都能改用消费级 Key；原 Windows 凭据与本机凭据须区分。

- 2026-11-05：用户明确大图分镜需要直接用左右方向键逐张浏览。此类审图交互应复用按钮的首尾与草稿逻辑；快捷键只作用于当前可见大图，不能抢占提示词光标、页码输入、下拉选择或其他 Tab 的方向键。

- 2026-11-04：用户纠正分镜“增加角色参考图”的来源：只能选择创建任务时已导入的角色，不能在结果页重新上传。对已有素材的“添加”先追溯任务内素材池；前后端都以该任务的原始 cast 绑定为来源，禁止将通用 uploads 目录当作可选角色库。

- 2026-11-04：用户明确分镜参考图只有角色图可以修改。展示与编辑权限必须区分：场景／道具总表和首张分镜锚点只读，增删仅作用于当前分镜的角色图；后端重建固定参考图，不能只靠隐藏按钮限制。

- 2026-11-02：用户要求逐步骤核对工作台与 CLI。一层 UI 不应重新实现 film 时间归一化或凭猜测增加 API key 必填条件；优先调用 film.load/plan/refs，并用同输入结果对照测试。
- 2026-11-02：用户要求单镜审图和成熟播放器。交付媒体流程时，要检查“看到结果→修改一个结果→更新下游产物”是否可完成；原生 video 不能替代用户明确要求的播放器组件。局部改图后必须标记旧视频待更新，不能把旧成片当作更新后的结果。
- 2026-11-02：用户指出 film JSON 不应要求手工拼接图片路径。导入内容后应将参考位转换成可见的待上传清单，路径由程序管理；上传绑定与故事源 JSON 分开，切换脚本时清空旧绑定，不能要求用户理解本机路径才能完成流程。
- 2026-11-02：用户指出可能有 100+ 分镜，结果不能挤在创建表单旁。多素材生成应把输入和结果分成独立页面，分镜分页审阅；“生成结束”不等于“用户认可”，视频入口必须在服务端验证审核完成，改图后撤销相关确认。

- 2026-11-02：用户选择大量分镜统一确认出片，不需要逐张打勾。可选问题回复后应立即同步界面、后端和文档，删除尚未交付且不再需要的逐张审核实现；用整批版本校验防止旧页面确认新图片。

- 2026-11-02：用户明确要求默认真实生成。创建页的 JS 初始状态、HTML 按钮状态和使用说明必须同步，离线演示仅由用户主动切换，不擅自作为默认工作模式。

- 2026-11-02：用户明确结果页的分镜图与视频片段用并列 Tab，开始生成视频后自动切到视频片段。阶段自动切换只触发一次，不能让轮询覆盖用户之后手动选择的 Tab；两类素材保留独立分页。

- 2026-11-02：用户要求创建页默认整条片、JSON 初始为空，示例改为下载入口。HTML 与 JS 默认状态必须一致；下载示例不能写入或覆盖编辑器，清空输入不能显示格式错误。导入支持 .json / .txt 内的 JSON 内容及 UTF-8 BOM。最终视频需有明确下载按钮，不能仅藏在产物链接中。

- 2026-11-02：用户补充故障发生在另一台 Windows 设备。生成任务异常先确认设备和任务；本机成功日志不能用于判断远端结果。远端诊断需要对应日志、状态和输出文件信息。

- 2026-11-03：用户说“暂停字幕检查这个步骤”是在要求停用程序中的检查阶段，不是暂停开发任务。按明确指向的产品步骤修改运行行为；暂时停用应保留恢复能力。

- 2026-11-07：用户指定项目对外名称为“视频自动生成工作台”。后续案例与展示材料统一使用该名称，标题、页眉、PDF 元数据和交付文件名一起检查；H3 仅作为底层技术名称保留。
