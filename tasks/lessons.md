# 项目协作经验

- 2026-11-04：用户纠正分镜“增加角色参考图”的来源：只能选择创建任务时已导入的角色，不能在结果页重新上传。对已有素材的“添加”先追溯任务内素材池；前后端都以该任务的原始 cast 绑定为来源，禁止将通用 uploads 目录当作可选角色库。

- 2026-11-04：用户明确分镜参考图只有角色图可以修改。展示与编辑权限必须区分：场景／道具总表和首张分镜锚点只读，增删仅作用于当前分镜的角色图；后端重建固定参考图，不能只靠隐藏按钮限制。

- 2026-11-02：用户要求逐步骤核对工作台与 CLI。一层 UI 不应重新实现 film 时间归一化或凭猜测增加 API key 必填条件；优先调用 film.load/plan/refs，并用同输入结果对照测试。
- 2026-11-02：用户要求单镜审图和成熟播放器。交付媒体流程时，要检查“看到结果→修改一个结果→更新下游产物”是否可完成；原生 video 不能替代用户明确要求的播放器组件。局部改图后必须标记旧视频待更新，不能把旧成片当作更新后的结果。
- 2026-11-02：用户指出 film JSON 不应要求手工拼接图片路径。导入内容后应将参考位转换成可见的待上传清单，路径由程序管理；上传绑定与故事源 JSON 分开，切换脚本时清空旧绑定，不能要求用户理解本机路径才能完成流程。
- 2026-11-02：用户指出可能有 100+ 分镜，结果不能挤在创建表单旁。多素材生成应把输入和结果分成独立页面，分镜分页审阅；“生成结束”不等于“用户认可”，视频入口必须在服务端验证审核完成，改图后撤销相关确认。

- 2026-11-02：用户选择大量分镜统一确认出片，不需要逐张打勾。可选问题回复后应立即同步界面、后端和文档，删除尚未交付且不再需要的逐张审核实现；用整批版本校验防止旧页面确认新图片。

- 2026-11-02：用户明确要求默认真实生成。创建页的 JS 初始状态、HTML 按钮状态和使用说明必须同步，离线演示仅由用户主动切换，不擅自作为默认工作模式。

- 2026-11-02：用户明确结果页的分镜图与视频片段用并列 Tab，开始生成视频后自动切到视频片段。阶段自动切换只触发一次，不能让轮询覆盖用户之后手动选择的 Tab；两类素材保留独立分页。

- 2026-11-02：用户要求创建页默认整条片、JSON 初始为空，示例改为下载入口。HTML 与 JS 默认状态必须一致；下载示例不能写入或覆盖编辑器，清空输入不能显示格式错误。导入支持 .json / .txt 内的 JSON 内容及 UTF-8 BOM。最终视频需有明确下载按钮，不能仅藏在产物链接中。
